# Changesets

Hello and welcome! This folder has been automatically generated by `@changesets/cli`, a build tool that works with multi-package repos, or single-package repos to help you version and publish your code. You can find the full documentation for it [in our repository](https://github.com/changesets/changesets).

We have a quick list of common questions to get you started engaging with this project in [our documentation](https://github.com/changesets/changesets/blob/main/docs/common-questions.md).

## Adding a changeset

When you make a change to a published package, add a changeset describing it:

```bash
npx changeset
```

Pick the affected packages, the bump type (patch / minor / major), and write a one-line summary. The CLI writes a markdown file into this directory. Commit it alongside your code change.

When changesets are merged into `main`, the release workflow consumes them to compute new versions, update `CHANGELOG.md`, and publish to the **public npm registry** under the `@pineappleui` scope. `access` is `"public"` in `config.json`, and each publishable package repeats it in its own `publishConfig` — npm defaults scoped packages to `restricted`, so both are load-bearing.

`ignore` is deliberately empty. The tooling packages (`@pineappleui/tsconfig`, `@pineappleui/eslint-config`, `@pineappleui/vitest-preset`) are kept out of the release flow by `private: true` plus `privatePackages: { "version": false, "tag": false }`, **not** by listing them in `ignore`: changesets errors when an ignored package sits in the dependency graph of a non-ignored one, and all three are devDependencies of `@pineappleui/tokens`.
